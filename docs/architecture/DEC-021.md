# DEC-021 — Segurança e Proteção de Dados

**Status:** Aprovada
**Data:** 02/09/2026

## Contexto

Auditoria de segurança completa revelou vulnerabilidades e dados latentes que precisam ser corrigidos antes de produção. O projeto possui boa base (Firestore rules, autenticação, isolamento por UID) mas expõe riscos em configuração, dados e código legado.

## Decisão

Implementar camadas de segurança progressivas para proteger dados e funcionalidades:

### 1. Configuração Segura (IMEDIATO)

- **Variáveis de ambiente** para todas as chaves API e configurações sensíveis
- **Remover chaves hardcoded** de `firebase-config.js` e `src/config/firebase.js`
- **Arquivo `.env.example`** atualizado com todas as variáveis necessárias
- **`.gitignore`** já exclui `.env` (confirmado)

### 2. Proteção contra XSS (CURTO PRAZO)

- **Content Security Policy (CSP)** no `index.html`
- **Restringir fontes de scripts** apenas para domínios confiáveis
- **Evitar `unsafe-inline`** e `unsafe-eval` quando possível
- **Domains permitidos:** `fonts.googleapis.com`, `cdnjs.cloudflare.com`, `www.gstatic.com`

### 3. Limpeza de Dados Expostos (IMEDIATO)

- **Remover badge** "DADOS LOCAIS . SEM BACKEND" do HTML
- **Remover console.log** de produção em `firebase-config.js`
- **Remover configuração duplicada** - manter apenas `src/config/firebase.js`
- **Limpar dados demo** hardcoded (gráficos, modelo de moto)

### 4. Proteção de Operações (CURTO PRAZO)

- **Logging de erros** nas bridges (não ignorar silenciosamente)
- **Estados de sincronização** visíveis ao usuário
- **Validação de entrada** antes de persistir no Firestore

### 5. App Check (MÉDIO PRAZO - DEC-018)

- **Configurar Firebase App Check** antes de produção
- **`enforceAppCheck: true`** nas Cloud Functions
- **Ativar após testes** no Emulator
